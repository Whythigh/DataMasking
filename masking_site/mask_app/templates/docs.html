API documentation

One endpoint. Send a file, get it back with personal data masked — as a file, or as a table ready to paste into an LLM. Everything below works with the API key issued when you subscribe.

Overview

The DataRepli API takes a spreadsheet, finds the columns containing personal data, replaces those values with realistic substitutes, and returns the result. Amounts, dates, codes and other non-identifying fields are left untouched.

  • Accepts .xlsx, .xls and .csv files
  • Detects personal data automatically — no configuration needed
  • Processes every sheet in a workbook in a single call
  • The same original value maps to the same replacement across all sheets
  • Returns either the masked file or a Markdown table for LLM prompts
  • Files are processed in memory and never stored

Base URL — all requests go to https://www.datarepli.com

Authentication

Every request needs your API key in the Authorization header, using the Bearer scheme. Your key is shown once, on the page right after you subscribe.

HTTP header 
Authorization: Bearer dk_live_your_key_here

Keep your key private. Store it as an environment variable rather than writing it into code that gets committed or shared. Anyone with the key can use your quota.

API access requires a paid plan. Keys on the free tier will receive a 403 response — the free tier covers the web tool only.

Quickstart

A complete working example. This reads a local Excel file, sends it for masking, and writes the masked version back to disk.

Python 
import base64, requests

API_KEY = "dk_live_your_key_here"

# 1. read the file and encode it
with open("customers.xlsx", "rb") as f:
    encoded = base64.b64encode(f.read()).decode()

# 2. send it for masking
response = requests.post(
    "https://www.datarepli.com/api/v1/mask-file",
    headers={"Authorization": f"Bearer {API_KEY}"},
    json={
        "file_base64": encoded,
        "file_type":   "xlsx",
        "auto_detect": True
    }
)
result = response.json()

# 3. write the masked file back to disk
with open("customers_masked.xlsx", "wb") as f:
    f.write(base64.b64decode(result["file_base64"]))

print("Rows masked:", result["rows_processed"])
print("Columns changed:", result["fields_masked"])

Same request with curl

bash 
# encode the file, then post it
FILE=$(base64 -w 0 customers.xlsx)

curl -X POST https://www.datarepli.com/api/v1/mask-file \

Mask a file

POST https://www.datarepli.com/api/v1/mask-file

Send a base64-encoded file as JSON. The response contains either the masked file (also base64-encoded) or a Markdown table, plus a record of what was changed.

Request parameters

ParameterTypeDescription
file_base64required string The file contents, base64-encoded.
file_type string Either xlsx or csv. Defaults to xlsx.
auto_detect boolean Find personal data automatically. Defaults to true. Set to false to control masking entirely with rules.
output_format string Either file (default) to get the masked spreadsheet back, or markdown to get an AI-ready table instead.
max_rows integer Caps how many rows per sheet appear in the Markdown output — useful for staying inside an LLM's context window. Only applies when output_format is markdown.
force_mask array Column names to always mask, even if detection didn't flag them.
never_mask array Column names to always leave untouched, even if detection flagged them.
rules object Explicit per-column instructions, e.g. {"Email": "mask", "SSN": "redact"}. Used when auto_detect is false.

Masking strategies

ValueEffect
maskReplaces the value with a realistic substitute of the same shape.
redactReplaces the entire column with ***. Use for values that shouldn't survive in any form.

Excel responses include an extra sheet named DataRepli Summary, listing every column in the file and whether it was masked or left unchanged.

Markdown output

Set output_format to markdown and you'll get a formatted table back instead of a file — ready to drop straight into an LLM prompt with no file handling at all.

It's a compact representation: fewer tokens than JSON for the same data, and structured so models read the columns correctly.

Python 
import base64, requests

with open("customers.xlsx", "rb") as f:
    encoded = base64.b64encode(f.read()).decode()

response = requests.post(
    "https://www.datarepli.com/api/v1/mask-file",
    headers={"Authorization": "Bearer dk_live_your_key_here"},
    json={
        "file_base64":   encoded,
        "file_type":     "xlsx",
        "auto_detect":   True,
        "output_format": "markdown",
        "max_rows":      500
    }
)

table = response.json()["markdown"]

# feed it straight into an LLM — no file upload needed
prompt = f"Summarise the overdue invoices in this data:\n\n{table}"

FieldDescription
markdownThe masked data as a Markdown table. Multiple sheets appear as separate sections with ### headings.
truncatedtrue if max_rows cut any sheet short, so you know some rows are missing.

Row usage is identical either way. Every row is masked and counts against your quota regardless of format — max_rows only limits what appears in the response, not what gets processed.

How detection works

Each column is checked twice before a decision is made.

First, the column name. Headers are matched against known indicators of personal data — name, email, phone, iban, ssn, address, and variations like approved_by or created_by that commonly hold people's names.

Then the values. If the header gives nothing away, a sample of the column's contents is checked against patterns for emails, IBANs, phone numbers and ID numbers. This catches personal data hiding in columns named col_7 or data.

Columns matching neither check are left completely untouched — which is why amounts, dates, cost centres and account codes survive intact.

Detection is good, not perfect. A column of plain first names under a meaningless header has no reliable signature and may be missed. Always check the fields_masked response or the summary sheet, and use force_mask for anything sensitive that detection didn't catch.

Controlling which columns are masked

Automatic detection can be corrected in both directions without turning it off.

JSON request body 
{
  "file_base64": "...",
  "file_type": "xlsx",
  "auto_detect": true,

  // mask these too, even though detection missed them
  "force_mask": ["Internal_Notes", "col_7"],

  // leave these alone, even though detection flagged them
  "never_mask": ["Region", "Product_Name"]
}

For complete manual control, set auto_detect to false and pass a rules object naming each column and its strategy. Columns not listed are left unchanged.

JSON request body 
{
  "file_base64": "...",
  "file_type": "csv",
  "auto_detect": false,
  "rules": {
    "Customer_Name": "mask",
    "Email":         "mask",
    "SSN":           "redact"
  }
}

Multi-sheet workbooks

Every sheet in an Excel file is processed in one call — no need to split the workbook or make separate requests.

Replacements are consistent across sheets. If the same customer appears in three different sheets, they become the same replacement identity in all three, so relationships between sheets survive masking and joins still work.

In Markdown output, each sheet becomes its own section headed with ### and the sheet name, so an LLM can tell them apart. Single-sheet files return just the table with no heading.

Consistency applies within a single request. Sending the same file twice produces two different sets of replacements — mask related data together in one call.
